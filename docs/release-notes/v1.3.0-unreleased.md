# CodePilot1C 1.3.0 — не выпущено

**Статус:** версия не тегирована и не имеет GitHub Release. На update site опубликована preview-сборка
`1.3.0.20260817-1245` из `64c45d95`; acceptance живого EDT по BSL-заглушкам форм (W1) ещё не закрыт.

## Изменения OSGi API

В версии 1.3.0 удалены следующие элементы API:

- `ProviderContextResolver`;
- API backend-оптимизаций в `ProviderCapabilities` и `ProviderUtils`;
- provider state в `ToolSurfaceContext`;
- прежний contributor с backend-ориентированным именем.

Compatibility shims для удалённых API не предоставляются. Версионные ограничения на уровне
OSGi-метаданных не введены, поэтому resolver не обнаружит эту несовместимость. Внешние overlay
bundles необходимо мигрировать и повторно скомпилировать против API 1.3.0.

При этом сохранены generic OpenAI-compatible transport и content fallback, а также внешние Qwen eval/runner assets.

## Поверхность инструментов в чате ограничена профилем агента

`ChatView` формирует список инструментов для модели через профильный gate: в запрос попадают только
явно перечисленные статические инструменты и динамические инструменты, для capability которых профиль
имеет явный runtime-grant. Сам факт динамической регистрации MCP/UI-инструмента не даёт capability.
Раньше в чат уходил полный список зарегистрированных инструментов независимо от профиля.

Allowlist'ы профилей при этом не сокращались: изменилась не конфигурация профиля, а сама поверхность
чата — она стала считаться по профилю. Пустой allowlist теперь имеет единое точное значение во всех
runtime-gate: **ни одного статического инструмента**, а не wildcard. Внешние реализации
`AgentProfile`, которые использовали пустой набор как «разрешить всё», должны перечислить статические
имена явно и отдельно переопределить `getDynamicToolGrant()` до проверенного уровня runtime-доступа.

Удалённые MCP-аннотации не являются доверенной границей и могут только повысить риск. По умолчанию
каждый MCP-инструмент регистрируется как `MUTATING`, включая неаннотированные инструменты и инструменты
с `readOnlyHint=true`. Понижение конкретного инструмента до `READ_ONLY` возможно только через локальную
конфигурацию сервера `trustedReadOnlyTools` — список точных исходных имён tools этого сервера. Любая
противоречивая/невалидная аннотация, `destructiveHint=true` или `readOnlyHint=false` возвращает такой
инструмент к `MUTATING`. Мутирующие динамические вызовы требуют подтверждения даже при отсутствии
совпавшего permission-правила.

Профиль фиксируется один раз на ход чата и берётся из instance-preference `chat.profileId` узла
`com.codepilot1c.core`. Это профиль поверхности инструментов конкретного хода чата, а не MCP session
profile, для которого существует отдельная preference-страница. Отдельной страницы настроек именно
для `chat.profileId` нет; при пустом значении действует профиль по умолчанию `build`.

Вызов инструмента, отсутствующего на поверхности профиля, отклоняется детерминированно
(`reason_code=tool_not_in_profile`, `layer=profile`) до начала исполнения.

## Изменение `FormRecipeResult` — внутреннее, вне OSGi API

Канонический конструктор record `FormRecipeResult` сокращён с девяти компонентов до восьми: два поля
`List<String>` (записанные и пропущенные BSL-заглушки обработчиков) заменены одним
`HandlerStubReport`. Читающие аксессоры `handlerStubsWritten()` и `handlerStubsSkippedExisting()`
сохранены.

Это **не** изменение OSGi API и не относится к списку удалённого API выше: пакет
`com.codepilot1c.core.edt.forms` отсутствует в `Export-Package` бандла `com.codepilot1c.core`,
поэтому внешние overlay-бандлы этот тип не видят и мигрировать им нечего. Изменение затрагивает
только код внутри `com.codepilot1c.core`.

## Учётные данные инфобазы больше не выдаются модели

`get_infobase_credentials` больше не возвращает сохранённый пароль. Это намеренно несовместимое
изменение payload для внешних потребителей: вместо поля `password` инструмент сообщает
`password_available`, детерминированные `password_delivery`/`password_delivery_reason` и
`login_strategy`. Значения `/P`, а также содержащие `Pwd=` или `Password=` значения
`/IBConnectionString` в `additional_parameters` заменяются на `<redacted>`.

Инструменты с тегом `sensitive` больше не входят в wildcard (`*`) MCP Host; для экспозиции требуется
явно указать имя инструмента. Даже при явной экспозиции plaintext-пароль не возвращается. Содержимое и
текст ошибок результатов sensitive-инструментов не записываются в `~/.vibe/tool_calls.log` и trace:
сохраняются только тип результата, статус, длительность и длина пропущенного содержимого.

Автоматический вход сохранённым паролем пока недоступен. Поддерживаемые варианты — OS-аутентификация
или ручной вход самим пользователем непосредственно в открытой browser session; пароль нельзя просить
ввести в чат или передавать модели. Возврат безопасной автоматизации отложен до
`M4-TRUSTED-CREDENTIAL-CONSUMER`, где потребуется явный контракт доверия с конкретным потребителем.
Даже стратегия `no_password_required` намеренно не запускает автоматический вход: в текущей границе
разрешены только OS-аутентификация и ручной вход пользователя в browser session.

Это изменение не является общей санацией model-facing error envelope: текст исключения при ошибке
получения настроек доступа пока возвращается как раньше и требует отдельного security hardening.
