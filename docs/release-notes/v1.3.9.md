# CodePilot1C 1.3.9

## Cyrillic call graph correctness on EDT JDK 25

- BSL call parsing no longer relies on a leading regex word boundary, whose Cyrillic behavior
  differs in EDT's Axiom JDK 25 runtime.
- `edt_get_project_call_graph` and `edt_get_method_call_hierarchy` now include direct calls to
  Russian method names, while retaining file-path-qualified method identity.
- The Unicode-safe call matcher uses an explicit negative lookbehind for identifier characters;
  method-name suffixes cannot be matched from inside a longer identifier.
- Regression coverage verifies the live-shaped `HealthGETЗапрос` call to
  `ДиагностикаАртели` at line 9.

## Filesystem containment hardening

- GSD lock, state, backup, quarantine, and Markdown projection mutations now bind the project and
  target-directory identities before use and reject changed or escaped ancestry at mutation
  boundaries.
- Ship-scoped `write_file` publication uses the same guarded atomic-write path while retaining
  Eclipse workspace refresh and BM synchronization.
- Filesystem mutation now requires Java 17 `SecureDirectoryStream` and publishes only relative to
  validated, open directory handles. Providers without that primitive (including the macOS JDK 17
  default provider) fail closed before the first lock, temp, rename, cleanup, or publication.
- Read-only GSD inspection remains available on those providers. `loadReadOnly()` performs no lock,
  migration, recovery, projection, or pathname mutation: it rejects symlinks, requires lexical and
  real ancestry to agree, opens `state.json` with `NOFOLLOW_LINKS`, limits the read to 16 MiB, and
  rechecks file key, real path, type, size, and modification time for every component after reading.
  A deterministic adversarial test swaps the final path between the byte read and revalidation and
  proves the data is rejected while the outside tree remains unchanged.
- Java 17 has no portable secure relative directory-creation primitive. On a provider that does
  expose `SecureDirectoryStream`, GSD and ship parent directories must already exist and the error
  names the exact directory to pre-create. On a provider without it, capability failure is reported
  first: pre-creation is not suggested because it cannot enable mutation.
- GSD tool failures caused by this provider limitation, plus GSD Ship `write_file`, return the
  provider-neutral machine-readable `error_code=unsupported` instead of generic `io`.
- Workspace-bound project identity is carried through ship publication, preventing a project-root
  swap after the initial workspace containment check from binding an escaped replacement.
- Deterministic hook-based tests cover project/directory binding, lock open, temp creation,
  publication, cleanup, quarantine rename, and missing-parent/bootstrap boundaries. Linux tests
  exercise real secure handles; forced and native non-secure-provider tests assert byte-for-byte
  unchanged trees and fail-closed behavior.

## Local acceptance evidence

CI remains disabled by repository policy. Acceptance was run locally with Java 17, the pinned EDT
`2025.1.5+34`, Maven `package`, and explicit executed/skipped counts.

macOS focused contracts and portable-read suite:

```bash
mvn -Dedt.home='/Users/alex/Applications/1C/1CE/components/1c-edt-2025.1.5+34-x86_64/1cedt (2025.1.5+34).app/Contents/Eclipse' \
  -pl bundles/com.codepilot1c.core.tests -am \
  -Dtest=GsdStateStoreTest,GsdWorkflowServiceTest,GsdToolsTest,WorkspacePathContainmentTest \
  -Dsurefire.failIfNoSpecifiedTests=false package
```

Result: 173 discovered, 95 executed, 78 capability-skipped, 0 failures, 0 errors. Registration,
schemas, metadata, descriptions, strict integer parsing, required-criterion validation, portable
populated `gsd_get_state`, shipment sanitization/idempotency, forced non-secure read confinement,
and real unsupported tool envelopes executed. Mutation lifecycle and real wrong-phase envelopes
are among the explicitly capability-skipped cases and are exercised by the Linux run below.

Linux Docker real-`SecureDirectoryStream` filesystem/GSD/shipment suite (the local Maven 3.9.16
distribution is copied into a disposable Docker volume because the cached image contains Java 17
but not Maven):

tar -C /opt/homebrew/Cellar/maven/3.9.16/libexec -cf - . | \

docker run --rm --user 501:20 -v /Users/alex:/Users/alex \

## EDT 2025.1 compatibility

- Runtime access settings, database update, and configuration XML export use narrow reflective
  adapters for the API names used across supported EDT releases (`getSettings`/`resolveSettings`,
  `updateInfobase`/`updateDatabaseConfiguration`, and
  `exportConfigurationToXml`/`exportFullXmlFromInfobase`).
- Test doubles implement the interfaces shipped by the pinned EDT 2025.1.5+34 target so the test
  module compiles against the same acceptance runtime as production bundles.
