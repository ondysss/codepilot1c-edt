# Ограничения доступа роли через MCP

`inspect_role_rights` возвращает права, полные условия `restrictions` и
`availableRlsFields`: канонические имена полей и русские варианты. Табличные части
адресуются по отдельным полям, например `Items.Answer`.

`mutate_role_rights` поддерживает две дополнительные операции:

- `replace_rls` атомарно заменяет все условия одного явно выданного права.
- `clear_rls` явно удаляет его условия, сохраняя само право.

Пример аргументов для `edt_validate_request`, операция `mutate_role_rights`:

```json
{
  "project": "Example",
  "role": "Learner",
  "operations": [
    {
      "op": "replace_rls",
      "object_fqn": "Document.Attempt",
      "right": "Read",
      "restrictions": [
        {"fields": [], "condition": "WHERE FALSE"},
        {
          "fields": ["Ref", "Participant", "Items.Answer"],
          "condition": "WHERE Participant = &CurrentUser"
        }
      ]
    }
  ]
}
```

Передать тот же запрос в `mutate_role_rights` с полученным `validation_token`.
Потом независимо прочитать роль через `inspect_role_rights` и проверить
диагностику EDT.

Пустой `fields` означает остальные поля, которые не перечислены в других
условиях этого права. Это соответствует редактору EDT и сериализации
`restrictionByCondition` без `field`. Каждая замена обязана явно задать условие
для остальных полей, в том числе для добавленных впоследствии реквизитов.

Списки полей допускаются только для `Read`; для `Insert`, `Update`, `Delete`
задается одно условие записей с `fields: []`. Неизвестные поля, повтор одного
поля в нескольких условиях, пустые условия и пустой список `restrictions`
отклоняются до замены существующих ограничений. Снятие защиты требует отдельной
операции `clear_rls`.

Условия сохраняются без изменения текста. Инструмент не подтверждает синтаксис
запроса и фактические права пользователей: их проверяют диагностика, загрузка
конфигурации платформой и разрешенные/запрещенные действия отдельных учетных
записей. Другие роли пользователя могут предоставлять более широкий доступ;
одна ограничивающая роль не доказывает изоляцию.

Изменения выполняются через транзакцию модели EDT и штатную выгрузку прав,
без правки `Rights.rights` как текста и без автоматизации редактора.
