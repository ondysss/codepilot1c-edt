## Scope

### LIVE-01 — CommonCommand `commandParameterType` TypeDescription resolution

Make `create_metadata` and `update_metadata` resolve live EDT type specs for CommonCommand parameter types correctly.

Acceptance:

- `CatalogRef.<existing catalog>` resolves to a valid `TypeDescription` in the live workspace when valid.
- Invalid type specs fail deterministically with `INVALID_PROPERTY_VALUE` and useful candidates/hints.
- Existing unit/contract tests cover the live failure class using fakeable seams.

### LIVE-02 — `allow_auto_prefix=false` is ignored by validation

Make extension-name validation reject unprefixed names when callers explicitly set `allow_auto_prefix=false`.

Acceptance:

- Normal extension validation still returns `effectiveName`, `effectiveFqn`, and `autoPrefixed=true` for unprefixed names.
- With `allow_auto_prefix=false`, the same request is rejected before token issue.
- Error payload identifies the requested name, expected prefix, and effective name that would have been used.

### LIVE-03 — StandardCommandGroup create/update application

Make StandardCommandGroup aliases apply as EDT enum/literal values instead of metadata FQN references.

Acceptance:

- `StandardCommandGroup.FormCommandBarImportant` is accepted.
- `FormCommandBarImportant` is accepted after validation normalization.
- `create_metadata(CommonCommand, properties.group=...)` succeeds.
- `update_metadata(CommonCommand, changes.set.group=...)` succeeds.
- Unknown groups fail with available-values hints.

### LIVE-04 — Role rights validation-token contract

Expose and verify the correct validation-token flow for `mutate_role_rights`.

Acceptance:

- `edt_validate_request(operation=mutate_role_rights)` issues a token accepted by `mutate_role_rights`.
- The validation schema/tool surface documents `mutate_role_rights` as a valid operation.
- Unsupported extension config rights return structured diagnostics with available rights and extension context.
- Wrong-operation token mismatch remains covered as a negative test.

### LIVE-05 — Diagnostics classification

Classify the live diagnostics from `ДО.Артель` and `ДО` as either caused by this milestone or pre-existing/unrelated.

Acceptance:

- Extension-relevant diagnostics after smoke are zero or explicitly fixed.
- Unrelated diagnostics are listed with evidence and excluded from milestone closure.

## Out of Scope

- Broad cleanup of unrelated `ДО` diagnostics unless they are caused by CodePilot mutations.
- Deleting source/base configuration objects.
- Reworking the high-level planner beyond what is needed to unblock live primitive correctness.
