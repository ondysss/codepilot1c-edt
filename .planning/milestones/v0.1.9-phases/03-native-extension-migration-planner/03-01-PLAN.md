# Plan 03-01 — Native extension migration dry-run/apply planner

## Tasks

<task id="03-01-T1" title="Migration service DTO contract">
Design request/result DTOs for source project, extension project, source FQNs, copy flags, name strategy, rewrite flags, and dry-run/apply mode. Result must include effective names/FQNs, ordered operations, skipped unsupported operations, warnings, and diagnostics hints.
</task>

<task id="03-01-T2" title="Source metadata introspection">
Implement source introspection for top-level properties; child collections including attributes, dimensions, resources, tabular sections, commands, forms/templates where supported; module artifacts; role rights and extension config-right support where available.
</task>

<task id="03-01-T3" title="Dry-run operation planner">
Implement dry-run planning with no model mutation. Include exact low-level requests apply mode will execute and deterministic unsupported/skipped sections.
</task>

<task id="03-01-T4" title="Conservative apply mode">
Implement apply mode behind validation-token flow and confirmation. Create native top-level objects, children, TypeDescription fields, and modules through existing services. Do not delete source objects.
</task>

<task id="03-01-T5" title="Tool registration and Qwen compatibility">
Register the new tool in the correct built-in path. Keep description under 200 characters, flat schema with required fields, and add `QwenToolCallExamples` support.
</task>
